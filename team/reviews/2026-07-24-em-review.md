# Engineering Manager — Team Review & Operating Changes

Per founder directive: the EM actively manages the team, evaluates each role, and
improves the workflow proactively. First formal review, covering the founding sprint
(thesis → prototype → map v2).

## Role performance

**Software Architect — strong, one notable miss.**
Good calls: illustrated SVG map over react-native-maps (saved the demo from Expo Go
styling limits and the fictional-city problem); overscan+translate pan architecture;
in-memory store kept trivially simple. The miss: the "gestures starting on SVG never
reach a parent PanResponder on web" limitation was discovered *during QA*, not at
design time — the gesture overlay redesign cost a mid-build detour. Corrective: any
design that mixes input-handling layers now requires a written interaction-path note
("who owns the touch?") before implementation starts.

**Lead Software Engineer — high output, high quality.**
~30 files of clean, consistent TypeScript; strict typecheck passed first try on the
initial build; sensible reuse (one theme file, shared components). Two real bugs
authored (dating-deck stale closure; negative `gap`), both caught in self-review
before runtime. Watch item: resist building ahead of verified design decisions —
speed is currently a strength, not a risk, but the map-first directive raises the
cost of building the wrong thing.

**QA Engineer — the team's quiet MVP.**
The walkthrough-as-test-suite discipline caught every real defect: the swallowed
♥-tap, the web-drag/text-selection failure, zoom-button/mini-card overlap, label
collisions. The demo-script QA.md is now the de-facto acceptance contract.
Corrective: QA enters *design* reviews from now on (the SVG gesture issue was
detectable by asking "how do we test a drag?" at design time).

**EM (self-review) — two process failures.**
(1) Let implementation start on map v2 without a written interaction spec; the
gesture detour was the price. (2) Turn-scoped work left loose ends (README phone
instructions promised but not shipped with PATH caveat; QA.md not updated for the
world view) — closed in this cycle. The founder should expect loose ends to be
listed explicitly at the end of every report, not silently dropped.

## Operating changes (effective now)

1. **Design-before-build gate.** Any feature touching input handling, animation, or
   a new surface gets a written design note (can be brief) with an interaction path
   and a QA question ("how will we verify this?") *before* code.
2. **QA in design reviews**, not just after builds.
3. **Multi-agent design exploration for centrepiece features.** For the map-first
   directive we now run parallel independent design concepts + adversarial judging
   before committing (in progress). Single-designer tunnel vision is the biggest
   quality risk at this stage.
4. **Loose-ends ledger.** Every report to the founder ends with explicit unfinished
   items. Nothing gets silently dropped.
5. **Verification remains non-negotiable**: typecheck + demo-script walkthrough
   before any claim of "done"; phone (Expo Go) verification before any pitch.
